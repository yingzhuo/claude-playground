# JSR 380 Bean Validation 规范

## 适用范围

- **DTO**：必须应用 JSR 380 校验注解
- **VO**：不需要 JSR 380 校验（VO 仅用于数据展示，无用户输入校验场景）

## 通用规则

- 所有字段都必须标注 JSR 380 校验注解
- 所有 `String` 类型字段必须通过 `@Size` 指明 `max`（最大长度），值参考数据库字段定义
- 如果业务上有明确要求，`String` 类型字段应同时通过 `@Size` 指明 `min`（最小长度），例如：用户名不少于 2 位
- `@Size(max = ...)` 的数字不宜过大，应与数据库 DDL 保持一致，而非随意使用 `Integer.MAX_VALUE`
- 校验注解与 Swagger `@Schema` 的 `minLength` / `maxLength` 必须保持一致

## 常见字段校验

| 场景      | 必填                                        | 可选                          |
|---------|-------------------------------------------|-----------------------------|
| 字符串     | `@NotBlank` + `@Size(min = ?, max = ?)`   | `@Size(max = ?)`            |
| 数字      | `@NotNull` + `@Min` / `@Max`              | `@Min` / `@Max`             |
| 邮箱      | `@NotBlank` + `@Email` + `@Size(max = ?)` | `@Email` + `@Size(max = ?)` |
| URL     | `@NotBlank` + `@URL` + `@Size(max = ?)`   | `@URL` + `@Size(max = ?)`   |
| Boolean | `@NotNull`                                | 无需注解                        |

## 项目内置元注释

位于 `io.github.yingzhuo.claude.jsr380` 包下，可直接使用：

### `@PasswordStrength`

- 目标：`FIELD` / `PARAMETER`
- 校验密码强度：必须包含字母、数字和特殊字符
- 适用于注册、修改密码等场景的密码字段

```java

@PasswordStrength
@NotBlank
@Size(min = 8, max = 32)
private String password;
```

### `@PasswordMatch`

- 目标：`TYPE` / `ANNOTATION_TYPE`（类级别）
- 校验两个密码字段是否一致
- 适用于注册表单、修改密码表单等 DTO 类

```java

@PasswordMatch
public class RegisterDto {
    @PasswordStrength
    @NotBlank
    @Size(min = 8, max = 32)
    private String password;

    @NotBlank
    @Size(min = 8, max = 32)
    private String confirmPassword;
}
```

## 分组校验

- 一般情况下无需使用分组校验，一个 DTO 只服务于一个接口
- 如果一个 DTO 被多个接口共用，才考虑分组校验

## 禁止事项

- 禁止在 VO 上添加 JSR 380 注解
- 禁止使用 `@Valid` 嵌套校验 VO 中的集合或对象
- 禁止在 `String` 字段上省略 `@Size(max = ...)`，哪怕是数据库定义为 `text` 类型也需指定实际最大长度
- 禁止抛出 `ConstraintViolationException` 之外的校验异常（统一由全局异常处理器处理）
- 类级别的自定义校验注解（如 `@PasswordMatch`）必须与 `@Valid` 配合使用，否则不会被触发
